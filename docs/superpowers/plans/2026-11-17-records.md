# Records implementation plan

Goal: implement Records on feat/sheep without copying drawing/AI or User implementation.
Architecture: RecordPort creates drafts and marks card-ready. RecordSnapshotReader is a server-only read contract implemented by drawing/AI after integration. Completion freezes its validated snapshot and calls Sheep award in the same transaction. Missing provider returns RECORD_SOURCE_UNAVAILABLE; incomplete analysis is never invented.
Stack: existing Java17, Spring MVC/JPA, MySQL8, H2 tests.

## Confirmed requirements
- recordId only. Multiple completions/day; first earns 1, later 0.
- title is provided by the user in the completion request (required, 1–500 nonblank characters); original conversation and four analysis sections come from the server-side source snapshot.
- GET list default all dates, completion descending, keyset pagination; optional date.
- calendar latest completed nondeleted record per Seoul date; deletion reveals previous one.
- soft deletion preserves reward/source identity. No edits, no public draft creation because drawing calls RecordPort.
- CurrentUserProvider supplies identity. No User/auth implementation. No HTTP award endpoint.
